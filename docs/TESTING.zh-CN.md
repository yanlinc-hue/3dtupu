# 测试结果与已知局限

口径日期：2026-09-09。版本 0.5.0。已完成离线测试、桌面与手机尺寸的真实浏览器操作，以及此前的两组实际 API 测试；手机尺寸测试不是 iPhone Safari 真机验收。

## 已验证哪些能力

- `npm run test:hosted`：144 项离线测试全部通过，包括模型响应校验、密钥隔离、授权绑定、取消和迟到结果、原始聊天导入、范围与隐私过滤、商业关系边界、重名、工作台状态和加密恢复；新增旧页面契约拒绝，保证在限流、读体和付费调用前停止。
- `npm run test:graph`：服务端渲染检查，包括工作台四入口、导入向导、2D / 3D 筛选、快照与表单语义。不是浏览器点击或手机截图验收。
- `npm run build`：TypeScript 检查与构建通过。
- Wrangler 4.92.0 后端打包通过；Workerd 隔离运行的状态、连接诊断、7 个模型适配、原始聊天节点发现和取消链路均通过，外部调用为零。
- 实际虚构数据测试：本机同源 HTTP → Worker 处理逻辑 → 官方 OpenAI，GPT-4o 分别完成节点发现与关系分析；最终图谱通过产品校验。工作台加密保存／恢复往返通过。

所有实测内容为虚构，gold 在调用前冻结且未发送给模型。没有用客户真实聊天，也没有把 gold 调整到符合模型结果。离线测试通过数量不是模型准确率。

## 浏览器与公开视频验收

Chrome 两个全新隔离环境：桌面 1440×1000 与手机模拟 390×844，28 项记录通过。四入口、虚构联系人新增、笔记与待办保留、完成撤销、项目阶段与参与方、公开示范文件恢复和 5 类筛选的 2D/3D 一致性均通过。12 张截图无横向页面溢出，控制台和页面错误为零。没有外部网络或付费模型调用。

103 秒中文字幕视频录制真实 UI：导入虚构聊天、范围与隐私预览、临时配置占位密钥、两阶段授权、24 节点人工确认、2D/3D筛选、客户项目跟进、实际加密下载和重新打开。候选发现按保存的实测名单与上下文重建回放，关系解析使用已跑通结果；没有注入正式应用状态、跳过产品校验或重复付费。字幕明确省略了逐项名单确认过程。

未测 iPhone Safari 真机、客户自己的微信导出环境，以及向导容量异常交互。模型名单和更正仍需人工核对。

## 实际 GPT-4o：最终图谱评分

评分对象是模型加产品校验后**最终接纳的图谱**，不是原始模型草稿。原样本是已见过的修复回归集；新样本用于独立验证，但有人工补点，不能称完全自动。

| 项目 | 原含噪样本 | 新样本 |
| --- | --- | --- |
| 原始消息 → 进入分析的文本 | 73 → 70 | 24 → 22 |
| 跳过媒体／排除未来消息 | 2 / 1 | 1 / 1 |
| 最终关系记录 | 21 | 18 |
| 明确肯定关系：结构、状态命中 | 18/19（94.7%） | 15/15 |
| 明确肯定关系：再含角色、比例 | 17/19（89.5%） | 14/15（93.3%） |
| 全部结构：TP / FP / FN | 21 / 0 / 3 | 18 / 0 / 0 |
| 全部结构＋严格状态：TP / FP / FN | 21 / 0 / 3 | 17 / 1 / 1 |
| 再含已注册角色、比例：TP / FP / FN | 20 / 1 / 4 | 16 / 2 / 2 |

结构严格匹配有向两端、类型、项目、引荐人。精确率＝TP/(TP+FP)，召回率＝TP/(TP+FN)；错误状态或字段在该严格层级分别造成一个 FP、FN。原样本全结构精确率 100%、召回率 87.5%；加角色／比例与状态为 95.2%、83.3%。新样本全结构均为 100%，加角色／比例与状态均为 88.9%。这不是“总体准确率 100%”。

全部金标准分别是 24 和 18 条，含否定、计划／传闻、历史和更正记录；不能拿“记录被正确表示”理解为“所有商业断言真实”。只有聊天来源，肯定关系仍为待确认，不是已核实交易。

## 还没做好什么

原样本漏了 100% 持股、传闻收购和晚来持股更正；顾问关系存在但缺“财务顾问”角色字段。子公司方向、过去已完成投资不自动失效、明确否定和历史任职已正确表示。

新样本所有结构齐全，但晚来更正只得到“有分歧”，没有严格归为“不采用”；旧 9% 仍显示于冲突记录，不能视为当前确认持股。顾问角色输出“财务顾问服务”，与冻结 gold 的“财务顾问”是严格字符串差异，语义接近，不是凭空造关系。两份样本都未发现日常聊天造成额外业务边，但小样本不能证明所有噪声都能排除。

新样本在人工合并重复候选、核对项目名后，只发现 15/17 个目标节点；**衡浦银行、松汀资本是人工补齐**后才分析关系。原样本未补缺失主节点，但同样有人工确认，两个同名陈晨因身份未确认而排除，不能算自动消歧成功。

最终图谱不暴露结构化 `validFrom` / `validTo`，不能声称所有日期还原。历史截止日在引用中保留、状态正确，不等于已输出可查询的截止日期字段。若把预注册非空日期字段也纳入完整留存，新样本只有 15/18。

结果文件保存最终图谱与 HTTP 元数据，没有完整原始模型 facts。因此不能把最终漏项断言成模型本体漏项，也不能宣称零事实被后处理隔离。隔离提示与不完整结果必须保留可见说明。

## 发布前后还需做

本轮公网验收已通过：GitHub Pages 已发布 0.5.0 中文页面，Worker 状态版本为 `2026-09-09.5`、契约 `commercial-relations-v3`。全新 Chrome 打开正式域名，验证首页使用目标构建、中文指南适配 390px、3 份中文文档与示例/字幕返回 200；103.1 秒视频可播放并跳转到后段。页面错误、控制台错误及第三方请求为零；未输入密钥、未上传客户材料、未调用付费模型。

上线时发现 Cloudflare 自动插入统计脚本，CSP 当场阻止执行；现已通过 HTML 的 `no-transform` 响应头禁止注入，并重新检查实际线上 HTML 及浏览器。旧客户端请求返回 409，缺密钥返回 401，跨站返回 403，均未调用模型。

发布人员需按[部署说明](DEPLOY.zh-CN.md)同时更新 Pages 与 Worker，检查中文入口、同源 API、防跨站拒绝、无 key 行为、视频与样例下载，再进行真实浏览器和手机操作验收。未完成的项目应明确记为未测。

后续准确率评估应继续使用预先冻结的新样本，分别报告自动节点覆盖、人工补充数量、关系结构、状态和字段；保留失败次数与费用，不通过丢弃坏项或只计返回数量来宣布成功。客户真实数据测试需单独授权、缩小范围并完成隐私审核。
