# 怎么导入自己的资料

先选对入口：**「导入聊天」读微信导出；「导入关系资料」读本工具的关系 JSON；「打开文件」恢复加密工作台。** 三种格式不能混用。

本说明对应 2026-09-09 0.5.0 版本。初次体验请只用[全虚构聊天示例](https://3dtupu.com/examples/wechat-noisy.synthetic.json)或向导里的「试用虚构聊天」。中文字幕视频见[这里](https://3dtupu.com/demo/dealgraph-demo-zh.mp4)。

复现实测示例时，将分析截止日期设为 **2026-09-09**，这样测试中更晚的消息仍被排除；默认日期会随实际使用日期变化。

## 支持什么文件

支持 **Murmur 单会话 JSON v1**：每个文件对应一个会话，根字段包括 `wxid`、`name`、`format_version`、`messages`；消息包含时间、发送者、类型和 `text`。

这不是腾讯官方统一导出格式。微信迁移包、iPhone / iCloud / iTunes 备份、直接复制的微信数据库和任意聊天截图不能直接导入。网站不会自动读微信、提取密钥、重签应用或下载手机记录。请只处理你有权使用的文件，保留原文件备份。

## 四步完成

### 1. 选择文件，检查隐私

点击「导入聊天」→「选择聊天文件」，选择会话和北京时间起止日期。展开「逐条排除或编辑消息」，去掉家庭、健康、地址等无关内容；修改只影响本次导入，不改原文件。

查看「实际待发送文本」。原始微信标识会移除，可辅助隐藏手机号、邮箱、长号码和常见密钥，也可添加自定义隐藏词；这不保证完全匿名，姓名和正文仍可能敏感。图片、语音、文件和分享卡片不会解析。

仅选择文件和预览时，内容在浏览器处理，还没有发给模型。**只提取商业关系，不代表不会上传你保留的日常正文。**

### 2. 第一次同意：发现商业节点

点击「检查完毕，连接大模型」，选择服务商和模型，把自己的 API 密钥填入密钥框，点击「临时配置密钥」。不要把密钥发给聊天助手、截图或提交 Git。

检查发送范围与费用说明，勾选本次上传同意，再点「发送并发现节点」。这一步发送所选文本，产生 API 费用，但只返回候选人物、机构和项目，尚未生成关系。

线上请求经过 Cloudflare 中转后到达所选服务商。选择国内模型不代表全链路只在境内；上传前请查看页面里的服务商数据说明。程序不持久化材料或密钥，不等于网络平台和模型服务商零保留。

配置密钥和检查网站服务不验证余额；密钥只暂存当前页面，30 分钟、切换模型或关闭导入后清除。网站不提供站长共享额度。

### 3. 人工确认名单

检查姓名、机构、项目和别名。仅对确认是同一个对象的重复候选执行合并；同名不同人不要强行合并，身份不清就保留待核对或移除。缺少商业参与方时，可以按原文补充，不要凭印象新增事实。

**移除节点不会删除待发送正文中的姓名。** 如果该姓名也不能上传，请返回材料页编辑或隐藏。

检查完勾选名单确认，再点「确认名单，继续」。模型只能在你确认的名单内连接关系；漏节点会导致漏关系。身份确认是人工步骤，不是工商身份核验。

### 4. 第二次同意：生成关系

再次核对实际待发送文本、名单、服务商和模型，勾选第二次同意，点击「发送并生成商业关系图」。这一步再次发送文本及确认名单，**另行计费**。

成功后新增独立资料集，旧客户和记录保留，可在上方切换；跨资料集同名对象不会自动合并。修改名单可返回上一步，不必重复付费发现；返回修改材料会作废旧名单和同意。

取消、超时或校验失败时不会拿部分结果覆盖原图。不自动付费重试，但已经处理的请求仍可能计费；不要连续重复点击来测试余额。

## 怎么看关系

「客户」看个人／机构关系，「项目」看参与方和跟进，「关系」看 2D / 3D 网络。箭头表示方向，项目限定适用范围，引荐会显示引荐人；切换图谱维度不调用模型。

| 状态 | 怎么理解 |
| --- | --- |
| 明确记录 | 达到工具的记录支持条件，仍不等于外部真实性认证 |
| 待确认（review） | 单份聊天里的肯定、计划或待定信息不能当成已核实事实 |
| 历史 | 原文表明已结束的任职或关系，不代表现在仍然成立 |
| 有分歧 | 同一关系出现矛盾，例如旧持股说法与后来更正；先核对，别当当前事实 |
| 不采用 | 否定或不应采用的记录；客户速览可能默认隐藏，关系筛选和保存结果保留状态 |

工具不把同群、聊得多、发材料、普通饭局介绍或朋友借饭钱自动当成商业关系。结果仍可能漏项、误判字段或未完整处理更正，需要人工核对。

## 保存和下次恢复

点击「加密保存」，设置 **12–256 个字符**的独立强密码，再点「加密并下载」。在电脑「下载」或手机「文件」中找到 `.dgvault` 后，才点「我已找到保存文件」。这不是自动保存；后续修改要重新保存，刷新或关闭可能丢失未保存内容。

下次点「打开文件」，选择 `.dgvault`，输入该文件的保存密码，确认替换当前工作台。它不是微信密码、开机密码或 API 密钥；密码丢失无法找回。恢复只显示保存时快照，不重新调用模型、不表示关系现在仍有效。

加密文件包含导入分析文本、关系、客户、项目、笔记和待办，不含 API 密钥、保存密码或上传同意。保存／恢复在浏览器完成，不上传；已解锁页面仍可能被同设备用户或恶意插件读取。

[加密工作台示例](https://3dtupu.com/examples/demo-workbench.dgvault)仅含虚构数据，示例密码为 `Demo2026!Graph`。它应使用「打开文件」，不是「导入关系资料」。公开示例密码绝不能用于客户资料。

## 文件太大或导入失败

- 原始读取最多 10 个文件、合计 20 MB、5 万条消息；不代表全部自动上传分析。
- 一次所选文本最多 6 万字符、6 批、120 个确认节点。单条消息超过 1 万字符需人工编辑或排除；请保留相关否定、更正与前后文，不只挑肯定句。
- 工作台最多 20 个资料集；加密前内容最多 10 MB，打开的加密文件最多 16 MB。
- 格式错误：先确认入口和格式；不要给迁移备份改个 `.json` 后缀冒充支持文件。
- 名单／关系校验失败：当前结果没有完成，原工作台保留。先看安全提示并缩小或核对材料，不要宣称图谱已经更新。
